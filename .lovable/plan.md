# CSV Reports Audit & Premium Fix Plan

## Phase 1 — Root Cause (already audited)

**Where CSV is generated:**
- Reports Center: `ReportsView.tsx` line 132 → `downloadCSV(..., buildReportCSV(reportType, aggregation))` from `src/lib/reportCsv.ts`.
- Parking: `ParkingExportButton.tsx` → `exportParkingCSV()` in `src/lib/parkingExport.ts` (hand-rolled, separate path).
- Monthly card: `MonthlySummary.tsx` line 198 → legacy `exportToCSV()` in `loadUtils.ts` (per-month only, not the Reports Center).

**Numbers audit — Reports Center CSV vs PDF:**
- Both consume the same `aggregateReport()` output (`ReportsView.tsx` lines 112–123) with identical `loads`, `expenses`, `fuelLogs`, `settings`, `range`, `preparedFor`.
- Same date range (`dateRange.from/to` from the shared `DateRangeFilter`), same report type, same cancelled/active filtering (`excludeCancelled` / `onlyCancelled` inside the aggregator), same gross/actual/diff/miles/fuel/expense/tax/net math.
- **Conclusion: numbers already match.** The user's perceived mismatch is almost certainly a *presentation* issue: the current CSV omits Completed/Cancelled split, Avg Rate/Mile, Avg Pay/Load, Total Expenses (fuel + other combined), Performance Snapshot, and uses raw codes (`loaded_miles_only`, `completed`) and unformatted numbers — making it look unrelated to the PDF.
- "Last Week" preset uses the same `from`/`to` strings for both exports; aggregator's `inRange` uses `endOfDay(parseISO(to))` so the end day is fully inclusive. No timezone bug at the export layer.

**Parking CSV:** Separate hand-rolled path, does not match PDF structure (PDF was already routed through `buildReportPdf` in the prior patch).

## Phase 2–5 — What will change

### 1. Rewrite `src/lib/reportCsv.ts` for premium structure
Same aggregator input, no math changes. New sections:

1. **Header block** (no commas in left column titles needing quoting):
   - `HaulTracker Pro — <Report Type>`
   - `Website,haultrackerpro.com`
   - `Prepared For,<preparedFor>`
   - `Date Range,<MM/DD/YYYY> to <MM/DD/YYYY>`
   - `Generated,<MM/DD/YYYY HH:mm>`
2. **Executive Summary** — `Metric,Value` table with all 18 required metrics (adds Completed Loads, Cancelled Loads, Total Expenses, Avg Rate/Mile, Avg Pay/Load, Deadhead %).
3. **Performance Snapshot** (for `full_profit`, `weekly_performance`, `year_end_tax`):
   - Gross Pay, Minus Fuel + Expenses, Minus Estimated Tax Reserve, Estimated Net Profit.
4. **Detailed tables** with section banner rows: `LOAD BREAKDOWN`, `EXPENSE BREAKDOWN`, `FUEL BREAKDOWN`, `TAX ESTIMATE` — each gated by report type (same gating as today).
5. **Disclaimer** row: estimated-tax disclaimer.
6. **Footer** row: `Generated by HaulTracker Pro — haultrackerpro.com`.

Formatting helpers:
- `money(n)` → `$0.00` (always with `$`, parentheses for negatives).
- `miles(n)` → `0.00`.
- `payModelLabel()` → `Loaded Miles Only`, `Total Miles`, `Loaded + Deadhead`, `Flat Rate`, `Manual`.
- `statusLabel()` → `Completed`, `Cancelled`, `Pending`.
- Date columns rendered `MM/DD/YYYY`.
- Blank rows between sections; CSV escaping unchanged (already safe).
- Empty range still emits header + summary with zeros + a "No data in selected range" notice row.

### 2. Route parking CSV through the premium builder
In `src/lib/parkingExport.ts`, rewrite `exportParkingCSV` to mirror what `exportParkingPDF` already does: build an `aggregateReport({...})` with parking-only expenses and call `buildReportCSV('expense', agg)` + `downloadCSV(...)`. Keeps row-level parking detail via the EXPENSE BREAKDOWN section. No schema/UI changes.

### 3. No changes to:
- `reportAggregator.ts` (math is correct and already shared)
- `reportPdf.ts`
- `loadUtils.ts` `exportToCSV` (legacy per-month export from `MonthlySummary`, out of scope for Reports Center)
- `computeLoadPay`, `loadMetrics`, `summarizeLoads`, tax math
- Auth/RLS/Stripe/routes/sidebar

## Phase 7 — Parking Reports audit (recommendation only)

Today: parking export lives only on the Parking page (driver-facing, current month). Tables exist (`parking_locations`, `parking_reports`, `parking_verifications`, `parking_favorites`, `driver_points`) but are **not** surfaced as a Report Type in the Reports Center.

Recommendation (not implemented in this patch):
- Add a `parking_activity` ReportType in a follow-up — driver-facing: reports submitted, locations covered, points earned, weekly activity. Reuse the same builder shell.
- Admin-facing parking intelligence stays in `/admin` (already there).
- Defer until approved to avoid scope creep.

## Phase 6 — XLSX recommendation (not implemented)

CSV cannot carry colors, merged cells, column widths, frozen rows, or currency formats — a true premium spreadsheet needs XLSX. Recommend adding `Export Premium Spreadsheet (.xlsx)` alongside CSV using `exceljs` (~200 KB, no native deps). Tabs: Summary / Loads / Expenses / Fuel / Taxes / Parking. Bold totals, brand navy header, currency + mileage number formats, autofit, frozen header row. **Will not build until approved.**
